# P03 execution plan

Owner: Codex; assigned scope: P03 only. Started 2026-09-22.

Prerequisites inspected: P02 is complete and its exact local/range RGB,
bounded-execution, failure-recovery, P01-regression, and full-parent evidence is
retained. The frozen Python source/environment and real raster corpus are
available. The repository remains an intentionally uncommitted initial tree,
with no active process or overlapping work.

1. Replace reference-venv discovery for distributable artifacts with a
   relocatable Linux bundle containing the Rust executable, the complete
   Rasterio/GDAL native dependency directory, GDAL/PROJ data, license notices,
   and explicit implementation/protocol/database identity. Keep the venv path
   only as a development fallback.
2. Build and smoke a container from that bundle against an unchanged real
   raster/database, then compare decoded output with the frozen Python capture.
3. Add a Lambda HTTP-event adapter and a zip artifact with a custom-runtime
   bootstrap. Test API Gateway v1/v2 request mapping, binary/base64 responses,
   errors, package contents/loading, and a real raster request locally. Do not
   deploy or incur cloud cost; retain an actual Lambda invocation as pending
   unless separately authorized and configured.
4. Expose the shared bounded Rust driver/render core through a minimal importable
   CPython extension, returning PNG bytes and translated errors. Prove import,
   successful real rendering, decoded-image parity, and stable error behavior.
5. Add a narrow legacy-SQLite compatibility writer sufficient for early
   Python-to-Rust and Rust-to-Python database round trips. It is feasibility
   evidence, not the complete transactional write API assigned to P05.
6. Implement a WSGI adapter boundary over the native HTTP-event operation and
   smoke it through a real WSGI invocation. Run focused tests, offline
   build/test/Clippy, P01/P02 regressions as relevant, inspect retained images,
   and update evidence, coverage, decisions/discoveries, README/status, and a
   resumable handoff.

Acceptance: every locally executable P03 exit in `process/execution/PHASES.md` has
retained evidence, artifacts do not discover `.venv-reference` at runtime, and
the same bounded raster core serves native HTTP, Python, WSGI, Lambda-adapter,
and container paths. The platform matrix distinguishes Linux x86_64 evidence
from untested platforms. A deployed AWS Lambda invocation remains explicitly
pending because this assignment does not authorize cloud deployment or spend.

Completed 2026-09-22. All locally authorized acceptance items passed. The
initial host-built Lambda binary exposed and then resolved RW-015 by moving the
target build into pinned `provided.al2023`. An actual AWS service invocation was
not authorized and remains an explicit external check. See
`process/execution/handoffs/P03.md` and `process/validation/evidence/p03/README.md`.
