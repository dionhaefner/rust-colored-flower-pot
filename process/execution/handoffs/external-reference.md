# External Terracotta reference handoff

- **Direction:** Remove the original Terracotta Python source from the RCFP tree. Obtain the frozen oracle only when needed for validation.
- **Change:** Removed tracked `python/terracotta`. `process/validation/tools/fetch-reference.py` downloads the pinned 0.10.1 PyPI sdist, verifies SHA-256, and atomically extracts it to ignored `.cache/reference`. `bootstrap-reference.sh` uses it by default; `TERRACOTTA_SOURCE_ARCHIVE` allows a cached archive. README, AGENTS, validation setup, notices, and contract source paths now describe the external reference.
- **Evidence:** [Local report](../../validation/evidence/p08/external-reference/README.md) records the PyPI hash, exact package/test comparison against the existing frozen snapshot, browser asset comparison, live and cached fetches, and a configured Flask `/keys` request, 53 upstream expression tests run from the downloaded source, and a rejected corrupt archive. RCFP Rust, wheel, and source archive builds after removal are recorded there. The local wheel has an unrepaired Linux tag and is not a release-wheel qualification.
- **Limits:** The existing historical reference environment was retained. A full new reference dependency environment was not created because the checked in lock and install commands were unchanged. The PyPI generated `_version.py` differs from the Git archive version file by commit metadata; its version is still 0.10.1. Historical evidence files may mention the formerly tracked source path but are not build inputs. The contract inventory and reconciliation script now resolve oracle source paths under `.cache/reference` without claiming a vendored Python implementation.
