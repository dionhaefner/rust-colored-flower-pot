# RCFP source-boundary correction

- **User direction:** Restore the original Terracotta Python source and use RCFP as the Rust project's identity, import, distribution and CLI.
- **Implemented:** `python/terracotta` is unchanged from Git. `python/rcfp` contains the installable native adapter and CLI; the wheel excludes the original source, and the obsolete old adapter was removed with user approval. Cargo package/binary are `rcfp`, and the shared library is `rcfp_core`. RCFP owns a byte-identical copy of the browser assets under `src/assets/client`, allowing the sdist to exclude the original source. README and operator steps describe `pip install .`, `import rcfp` and `rcfp`.
- **Validation:** [Local evidence](../../validation/evidence/p08/rcfp-source-boundary/README.md) records a built wheel, fresh CPython 3.12 install, exact real-raster Python/WSGI image, CLI, source install and loopback HTTP serve. Normal `pip install .`, isolated wheel builds, and a build/install from the source tarball pass with Rasterio 1.4.4/GDAL 3.10.3. Cargo check, 20 Rust unit tests, Python/shell syntax, formatting and Git diff checks pass. No remote CI or publication occurred.
- **Open:** Automatic approval review initially rejected removal of `python/terracotta_rust`; the user then explicitly approved it, and the obsolete adapter was removed. The original `python/terracotta` tree remains unchanged. The full original Python driver and Flask surface is not implemented under the RCFP import. Existing historical evidence for that surface predates the source boundary correction. Nonlocal platform wheels and release repair remain to qualify.
