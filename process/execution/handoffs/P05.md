# P05 handoff — metadata, ingestion and raster optimization complete

Date: 2026-09-23. Owner: Codex. Assigned phase: P05 only, now complete.
Next phase: P06. No outstanding P05 blocker or user question.

## Implemented

- Native full-image, nearest sampled/lazy and native-block chunked metadata;
  linear full/sample percentiles, ported Crick t-digest/moments, validity/nodata/
  NaN handling, WGS84 bounds, GDAL/GEOS hulls and arbitrary JSON extra metadata.
- Legacy SQLite create/insert/delete/overwrite and descriptions; unchanged
  schema/version/float32 blobs. Atomic two-table operations and explicit batches
  with rollback guards/savepoints. Skip-metadata overwrites retain old metadata.
- Lazy publication uses BEGIN IMMEDIATE, rechecks under lock, computes sampled
  metadata and commits once across threads/processes. Explicit read-only failures
  and failed-load rollback/retry. Default shape is 1024×1024, configurable through
  `TC_LAZY_LOADING_MAX_SHAPE` as a two-value JSON list.
- `ingest`, raster-pattern parsing, repeated/escaped/Unicode keys, RGB ordering,
  skip-existing/skip-metadata/quiet and per-insert commit behavior. `serve -r`
  creates an ephemeral SQLite database, serves lazy metadata and exact imagery.
- `optimize-rasters`: first-band data, dataset masks, reference 256×256 window
  sequence, overviews, all four resamplers, compression auto/zstd/deflate/lzw/none,
  memory/disk intermediates, reference reprojection grids, skip/overwrite/quiet
  and bounded nproc workers. Intermediate TIFFs/VRTs have ownership cleanup.
- Shared structured data-operation boundary and in-process CPython preparation
  API (`compute_metadata`, `DataStore`, atomic `batch`), independent of native
  server runtime Python. Full legacy Python compatibility remains P07.
- Retained Crick BSD and t-digest Apache notices in source and built packages.

Main new files: `src/raster/metadata.rs`, `src/raster/optimize.rs`,
`src/statistics.rs`, `src/ingest.rs`, `src/cli.rs`. Storage, CLI, C ABI, Python
adapter and packaging were extended. D-007 records ownership and compatibility
choices; RW-021–025 record quirks, repairs and narrow accepted roundoff.

## Preserved state and limitations

Everything started untracked and remains uncommitted; no user work was reset,
committed or deleted. Sibling Python checkout remains read-only. Frozen oracle:
`.cache/reference` and `.venv-reference`, with the P00 dependency environment.
Final packages: `process/validation/artifacts/p05-qualified` and `p05-qualified-python`.
Full runs/large TIFFs/earlier experiments remain under ignored `p05-*` artifacts;
small durable evidence is in `process/validation/evidence/p05`. No P05 process is running.
Abruptly terminated `serve -r` tests may leave their uniquely named temporary
SQLite files in `/tmp`, matching the reference's ephemeral-file behavior.

P06 owns non-SQLite stores, S3 snapshots and migrations; P07 owns complete legacy
Python contexts/types/exceptions/settings/imports and remaining CLI/operations.
P05's explicit native batch is atomic; do not silently reinterpret Python's
nested-connect commit quirk. The P05 metadata adapter exposes float32 percentiles
at the SQLite boundary; raw NumPy ndarray return fidelity remains P07.
GEOS must remain in any replacement GDAL package. Lazy computation holds the
SQLite writer lock, so writes serialize until it completes.

Previously recorded release gaps remain: actual AWS invocation, fresh AL2023
qualification, arm64/macOS/Windows, real S3/custom endpoints, physical multi-GiB
BigTIFF offsets, publisher-native alpha/broader geography and browser E2E. No new
cloud service was deployed or authorized and no release was published.
