# P02 handoff

Task / phase / owner: P02 / Codex, completed 2026-09-22.

Outcome: the Rust executable now serves compatible RGB tiles/previews with
default, numeric and legacy percentile stretches; independent partial masks;
legacy black-key transparency; non-square output; empty tiles; and repeated-band
de-duplication. Singleband and RGB raster reads accept local files, HTTP(S)
through GDAL `/vsicurl/`, and S3 paths through `/vsis3/`. Startup maps the
Terracotta S3 credential/endpoint variables to GDAL without logging secrets.

Execution is bounded at both HTTP and raster admission. Each raster worker owns
its GDAL runtime and all request datasets/VRTs; startup initializes the
process-global runtime serially (RW-013), while reads run concurrently with
unique `/vsimem` names. Defaults are three workers, eight queued raster jobs,
a 30-second response wait, 64 MiB raw-raster LRU cache, and 60-second remote TTL,
all configurable through the `TC_*` variables listed in the README. Cache keys
cover path/source generation, bounds, dimensions, and categorical mode. Full
queues return 503. Wait expiry returns 504 but does not cancel GDAL; native work
remains accounted until completion. `GET /__terracotta/metrics` reports bounds,
cache use, jobs, failures, RSS and handles. D-004 records the decision.

Validation: the retained fast run passed eight exact Python/Rust decoded-RGBA
RGB cases, including a narrow real-Sentinel red-only internal-mask derivative.
Repeated RGB submitted one raster read. Local and HTTP-range RGB were exact; the
first remote request used 22 range GETs and 15,281,896 bytes, and its warm repeat
added no traffic. Three cold concurrent RGB requests passed with peak native
concurrency three and 191,877,120-byte sampled peak RSS under 512 MiB. The
ordinary-scale side-by-side sheet was visually inspected with no visible
difference. See `process/validation/evidence/p02/fast` and RW-014.

The saturation run with one worker/one queue produced two 504 and eight 503
responses, recorded seven raster-admission overloads, drained both timed-out
native jobs, then recovered from a missing-raster failure and served a valid
cached image. The full 36,000 × 36,000 WorldCover publisher COG matched Python
exactly for local/range preview and z15 base-resolution detail, used four range
GETs and 196,608 bytes cold, no traffic warm, and peaked at 54,407,168-byte RSS.
The 26-case P01 exact differential, offline corpus/comparator/Rust checks,
Clippy `-D warnings`, and locked offline build also pass. Evidence is indexed at
`process/validation/evidence/p02/README.md`.

Limitations: no AWS/S3 credential variables were available, so `/vsis3/`, real
credentials, refresh and custom-endpoint behavior are implemented but not
integration-verified; the local range server does not clear that gap. The corpus
still lacks a physical multi-GiB BigTIFF with offsets beyond 4 GiB. The timeout
is not native cancellation, and client-disconnect semantics remain P07. RGB
color transforms and the exhaustive option/error matrix remain P04. Remote
SQLite metadata is still P06, not part of raster URL support. GDAL packaging
still depends on the P00 Rasterio venv development fallback (RW-012/P03).

Workspace: the repository still has no initial commit, so the entire tree is
untracked and must be preserved. Generated `.cache`, `target`, reference venv
and `process/validation/artifacts` remain ignored. P02 retained evidence is under
`process/validation/evidence/p02`; temporary databases and the derived mask TIFF are
removed by their runners. No process remains active.

Exact next action: execute P03. Package the complete GDAL/native library and
data-file runtime instead of discovering the reference venv, then prove a real
container read, Lambda event/artifact path, minimal Python binding operation,
WSGI boundary, and early Python↔Rust database round trip without bypassing the
shared bounded raster core.
