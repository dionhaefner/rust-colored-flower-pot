# P01 handoff

Task / phase / owner: P01 / Codex, completed 2026-09-22.

Outcome: the Rust executable now reads an existing Python-created Terracotta
SQLite database and serves a useful, compatible single-band slice end to end.
`terracotta serve -d DATABASE [--bind HOST:PORT]` exposes ordered keys, basic
dataset filtering/ordering/paging, GET metadata/column selection, and
single-band previews/XYZ tiles. The renderer preserves grayscale, viridis and
one supplied explicit palette; numeric/percentile stretches; categorical
nearest-neighbor behavior; reprojection/read resampling separation; padded VRT
reads; nodata/internal masks; non-square output; and the legacy default-sized
empty tile. Later routes/options remain unadvertised.

Architecture: `storage.rs` is the read-only legacy SQLite boundary and preserves
the major/minor version check, misleading W/S/E/N positional columns and native
float32 percentile blobs. `raster.rs` dynamically loads the stable GDAL C API,
owns datasets/VRTs within a request, and implements the original two-stage warp
and mask path. `image.rs` owns NumPy-compatible stretching/rounding, category
labels, the frozen viridis palette and PNG encoding. `http.rs` is a thin native
adapter. D-003 and RW-012 record the consequential runtime/package choice.

Validation: `validation/tools/check.sh` passed (offline corpus/subsets, 19
comparator mutation tests, eight Rust tests). Clippy with `-D warnings`, locked
offline build and locked offline tests passed. The P01 differential passed all
26 selected cases against the unchanged Python-created database, with exact
status/selected headers/JSON values and exact decoded RGBA for every retained
image. The native-scale side-by-side sheet was inspected and showed no visible
difference. See `validation/evidence/p01/fast/report.json` and
`side-by-side.png`.

The full 36,000 × 36,000 WorldCover publisher COG passed broad preview and z15
base-resolution detail comparisons exactly. The Rust server's sampled peak RSS
was 41,926,656 bytes under the 512 MiB budget. The evidence records its 85 MB
classic-TIFF bytes, six overviews, 1024 × 1024 blocks, 1.296 GB decoded value
plane and process I/O counters; no downsampled source was substituted. See
`validation/evidence/p01/stress/report.json`.

Limitations: the HTTP server is intentionally synchronous and the `/vsimem` VRT
name is process-fixed; P02 must introduce bounded worker ownership before
concurrent requests. RGB, remote/range reads, caches, overload behavior and
instrumentation are P02. The local executable discovers Rasterio's private GDAL
runtime from the P00 venv and re-executes with its sibling libraries; this is a
development fallback, not packaged deployment evidence (RW-012/P03). Writes,
POST metadata, complete endpoint/options, browser/Python adapters and other
backends remain assigned to later phases. Native alpha, retained valid-zero,
remote/cloud and physical multi-GiB/BigTIFF-offset checks remain open.

Workspace: the repository still has no initial commit, so all files appear
untracked; preserve the entire tree. Generated `.cache`, `target`, reference
venv and `validation/artifacts` remain ignored. P01 evidence under
`validation/evidence/p01` is retained. The Clippy component was added to the
workspace-local pinned toolchain. No server or other process remains active.

Exact next action: execute P02. Start by replacing the synchronous/fixed-name
GDAL request ownership with a bounded worker/queue design behind the existing
core interface. Then add RGB with partial-mask differential cases and local
range-served equivalence using the same subsets/full WorldCover COG. Preserve
the P01 exact decoded-image cases as regressions before adding concurrency,
caching, credentials or remote-path handling.
